## Economy

- **Economy identity is cross-server: `UserAccount` has no `guild_id`.**
- **`total_earned - total_spent == balance` must hold:** every applied positive delta bumps `total_earned`, every negative one bumps `total_spent`.
- **Money inputs are string `SlashOption`s parsed by `utils.amount_parsing.parse_decimal_amount`;** malformed text gets an ephemeral reply before any mutation. Reuse it for any number that can exceed Discord's int cap.
- **`UserAccount.avatar_url` is a last-seen cache (`utils.avatars.guild_avatar_url`); do not backfill existing URLs.**
- **Central-bank minting is bounded by the pool and the per-borrower ceiling, never by the approver.** Approval is any server administrator (`cogs/economy/views.py::is_guild_admin`), which anyone becomes by creating a server.
- **The pool's collateral is per guild; its debt is the whole bank's.** `guild_participant` is recorded only for a rewarded message's author and a `/central_bank` caller, never a `member:` target; it is append-only (leaves are invisible without the `members` intent), and `call_central_bank_loans` refuses borrowers outside the calling guild's `guild_participant` so an arbitrary guild admin cannot sweep wallets across the economy.
- **Central-bank capacity and borrower ceilings double-subtract debt across all lenders (`typings/economy.py::central_bank_credit_ceiling`, `services/economy/database.py::_central_bank_status_in_session`)**: `central_bank_credit_ceiling` counts personal loans (0% tax, optionally 0% interest) in `total_debt` so two accounts cannot lend minted funds back and forth to reset ceilings, and pool capacity keeps `CENTRAL_BANK_BASE_CAPACITY + ledger_balance` inside the second `- outstanding_principal` subtraction so alternating `/give` cannot mint without bound off a positive floor.
- **`StoredInteger` columns store canonical decimal text and do not hook `ORDER BY` (`utils/stored_integer.py`)**: arithmetic and comparisons run through SQLite UDFs, but bare `.order_by(Model.col)` sorts lexically (`"9" > "100"`), so DB-side rankings must build explicit decimal-aware order terms (`services/economy/database.py`).
- **Shared social and settlement events are public embeds with scheduled cleanup; personal state, malformed-amount and permission failures are ephemeral.** A validation failure found after the public defer (`/give`, `/games`) is a public expiring embed.
- **Exactly one faucet pays an action reward, `cogs/economy/cog.py::EconomyCogs.on_message`'s cooldown-gated per-message reward;** other cogs must not add a second (the system-funded mints that settle a loan or a game are not rewards).
- **`apply_vip_blackjack_bonus` and the loan-rate converters stay in `typings/economy.py`,** so code that only formats or settles a number never imports the ledger's engine module (#610).

## Games

- `lobby.py`'s base views keep `raise NotImplementedError`; do not convert them to `abc.ABC`.
- **No LLM anywhere in the games:** do not reintroduce the removed casino `SystemNarrator` banter, the bot-player `reason` text or any AI bot-player. The dealer is a label, not a Discord identity, and posts no narrator messages.
- **Each Blackjack seat and each Dragon Gate bet settles in one atomic step once it resolves:** validate or clamp bets up front, then settle through the helpers.
- **A human player sits at one started casino round at a time, Blackjack and 射龍門 alike** (Blackjack settles post-round with losses clamped at wallet balance while paying wins in full, so seating one balance at two rounds or moving funds out mid-round pays every win and loses at most once): a new game goes through the lobby's seats too. A Blackjack seat holds the most its round can take, and a Dragon Gate seat starts at 0 and updates after each settled bet to `max(round_state.player_delta(user_id), 0)` (`cogs/games/dragon_gate_views.py::DragonGateView._resolve_bet_locked`) so mid-round net winnings stay protected for 逆贏不拿 refunds until withdrawal or table close; **a new path that debits a user's wallet of their own accord runs under `services/economy/holds.py::spending` and checks `held_amount` / `spendable`**, as every existing voluntary debit does.
- **Action buttons are presence-based: an invalid control is removed, not disabled** — except controls are disabled while a table settles (`cogs/games/blackjack_views.py`) and on a timed-out lobby until its delete (`cogs/games/lobby.py`), via `cogs/games/interactions.py::GameView._disable_buttons`.
- **A settled table goes out through `games/interactions.py::publish_final_table`**, which schedules its deletion; never delete terminal public messages in a cog-local loop.
- **The blackjack bot player (`bot_player.py`, no LLM) may drive the casino ledger negative**: the owner asked for a strong bot, so house losses are not a bug to fix in it.
