## Discord Cogs & Surface Rules

- **A Discord `400001 Access to file uploads has been limited` on a guild days old lifted by itself (#719)**: check the guild's age before touching code.
- **A feature that shares schema, concepts or many helpers with an existing cog extends that cog** (the loan commands live in `cogs/economy/cog.py`); only a low-coupling feature gets a new one. Do not add a status or query command just for symmetry; fold the information into an existing command's embed, as `/balance` does (a preference: `/credit status` and `/central_bank status` exist).
- **A shared slash-option vocabulary is a `Literal`, never a `StrEnum`** (`typings/video.py::VideoQuality` has why and the sites a new preset must reach). `SlashOption(default=...)` is typed `Any` upstream, so `ty` cannot check a default.
- **Every root slash command must declare `integration_types=INSTALL_CONTEXTS` and `contexts=INTERACTION_CONTEXTS`** (`typings/commands.py`), and every slash command, group, and subcommand must localize `name_localizations` and `description_localizations` for `Locale.zh_TW` and `Locale.ja` and omit `default_member_permissions` (`tests/guards/test_capabilities.py`).
- **Every `View` and `Modal` must subclass `utils/logged_ui.py::LoggedView` / `LoggedModal` (never raw `nextcord.ui.View` / `Modal`), must not shadow any `View` attribute with a callback name, and every subpackage under `cogs/` must carry `__init__.py`** (`tests/guards/test_view_callbacks.py`).
- **Every cog's `setup(bot)` must be synchronous, and every `@tasks.loop` method on a `Bot` or `Cog` must catch `Exception` inside its body (`cli.py`)**: `DiscordBot.__init__` loads extensions before an event loop runs (an async `setup` aborts boot with `ExtensionFailed`), and an uncaught exception in a class-bound `@tasks.loop` silently stops the loop forever (`nextcord.ext.tasks.Loop._call_loop_function` prepends `_injected` to the bound default `_error`). `cli.py` is feature-agnostic: it upgrades only `cleanup.db` (`utils/message_cleanup.py`) and reads presence and emoji defaults from `typings/config.py::load_bot_config` (`src/discordbot/config.toml` + optional `./data/config.toml`), while each cog upgrades its own SQLite sections in `setup()` via `utils/sqlite_config.py::ensure_database_upgraded` and `migrations/env.py` loads only the active section's metadata lazily (`tests/guards/test_migrations.py`, `tests/guards/test_isolation.py`).
- **Observe interactions via `@commands.Cog.listener()` on `on_interaction`, never by overriding `DiscordBot.on_interaction` (`cogs/usage/cog.py`)**: `commands.Bot.on_interaction` is `Client.on_interaction` (which dispatches application commands), so overriding it silently breaks every slash command; `interaction.application_command` is not yet populated during `on_interaction`, so read the command path from `interaction.data`.
- **User-installed interactions in guilds the bot has not joined have `interaction.guild is None`**: read guild identity and permissions from `interaction.guild_id` and `interaction.permissions` (payload-resolved, requiring neither a cached guild nor the `members` intent).
- **Defer interactions before SQLite writes, catch failures in deferred button callbacks, and record every press on timeout-editing views**: SQLite lock waits can outlive Discord's 3-second ack window (`tests/guards/test_ack_before_write.py`); after `interaction.response.defer()`, an uncaught `Exception` or `CancelledError` leaves a button's message silently unedited; and nextcord restarts a `View`'s timeout on every press (refused presses included), so timeout/cleanup views subclass `utils/message_cleanup.py::PressBoundView`, edit through `utils/message_cleanup.py::edit_or_report`, and send tracked public view followups via `utils/interaction_responses.py::send_tracked_view_followup`.
- **Reuse shared runtime utilities instead of duplicating plumbing**: structured Discord `HTTPException` / `Forbidden` / `NotFound` reporting uses `utils/discord_errors.py::report_discord_failure`, fixed-cadence live preview edits use `utils/preview_editor.py::CadencePreviewEditor`, bounded in-memory caches use `utils/lru.py::BoundedLRU`, streamed HTTP downloads use `utils/file_downloads.py::stream_to_file`, and deep-research channel checks use `utils/research_access.py::research_access_denial` / `has_research_permissions`.
- **Nextcord multipart edits omit `content=None` and never rewind `File.fp`**: when editing a message with `files=` (including `embed_spacer_payload`), pass `content=""` to clear existing text (`utils/expansion_placeholder.py`, `gen_reply/streaming.py`); after a failed send/edit carrying `nextcord.File`, call `file.reset(seek=True)` or rebuild the `File` before retrying (`cogs/research/delivery.py`, `gen_reply/surface.py`).
- **Aligned-width embeds use `utils.discord_embeds.embed_spacer_payload(..., target=)`**: pass `target=` on edits (`is_edit=True`) so the existing spacer attachment is retained by id; re-uploading it on rapid edits trips Discord `400009`.
- **Content past embed limits is paginated, rendered to a PNG via `attachment://...`, or clipped with a visible notice (`utils/discord_embeds.py::clip_to_utf16_limit`); never truncate silently.**
- **Markdown headings render reliably only inside `embed.description`.**
- **Never hardcode a Discord attachment-size ceiling; read it through `utils/media_delivery.py::upload_limit_for(guild=...)`, also passing `interaction=` when the media goes out through one**.
- **Decide attach vs host vs drop only in `MediaDeliveryPlanner.plan`; keep the Discord send and the degradation policy at each site**. Pass `envelope_margin=MEDIA_ENVELOPE_MARGIN` for a combined attach or one riding with embeds, and keep every new site host-free under `MEDIA_HOSTING_ENABLED=false` (module docstring).
- **A Discord forward has empty `content` / `embeds` / `attachments`; its payload is in `message.snapshots`** (`gen_reply/input.py`).
- **`channel.history(before=..., oldest_first=True)` reverses each 100-message page on its own**, so past one page the order scrambles: fetch newest first and reverse the list yourself (`gen_reply/surface.py::TurnSurface.fetch_history`).
- **A slash command's first followup after a defer keeps the defer's flag**, so a public settlement after an ephemeral defer goes through `utils/interaction_responses.py::send_expiring_followup_after_private_defer`.

## Usage Records

- **Usage records (`utils/usage_log.py`, #429) cover slash invocations and AI replies only**: a research run gets no record of its own, since its launch is already a `reply.db` `research` row and the `/deep_research` or `QA` turn that started it is recorded as usual. `admin/usage_report.py` names only what was used, so a zero-use inventory comes from `gen_reply/capabilities.md`.

## SQLAlchemy ORM Modules

- **Omit `from __future__ import annotations` in SQLAlchemy ORM modules**: postponed evaluation causes ruff's `TC` rules to move annotation-only imports such as `datetime` under `TYPE_CHECKING`, breaking `Mapped[datetime]` mapper resolution at import time (`cogs/gen_reply/ask_store.py`, `cogs/gen_reply/feedback_store.py`, `cogs/research/database.py`, `services/memory/database.py`, `utils/server_settings.py`).
