# CLAUDE.md

Rules, invariants and traps the code at the edit site does not show: each bullet is the rule, at most a clause of why, and one pointer.

## Commands

All tooling runs through `uv`.

```bash
uv run discordbot                # run the bot
uv run pytest                    # tests, coverage gate: 80% (--cov-fail-under)
uv run pytest <path> --no-cov    # focused run; without --no-cov a subset exits 1 on that gate
uvx pre-commit run -a            # canonical pre-push check (= make fmt)
uvx pre-commit run ty -a         # type check alone; `uvx ty check` rejects --all-groups (a uv flag)
make gen-docs                    # regenerate docs/ from sources
```

Config comes from `.env` (see `.env.example`); only `DISCORD_BOT_TOKEN` is required to boot. OpenAI clients are lazy `cached_property`s, so an empty `OPENAI_API_KEY` fails at first use (a turn, or a non-empty memory resume in `on_ready`), not at boot. `GEMINI_API_KEY` unlocks every direct-to-Google path.

Debug from `./data/logs`, which holds logfire output only (`_TeeStream` is logfire's console stream, not a `sys.stdout` replacement): a `print()`, a stdlib logger with no logfire handler and whatever nextcord prints to `sys.stderr` never land there.

Reuse `tests/conftest.py` and the fakes in `tests/helpers/` before writing a new fake. Seven fixtures are AUTOUSE: `file_api_enabled_by_default` and `gemini_key_set_isolated` pin the two `.env` settings that would otherwise decide a test, and `economy_isolated_db`, `usage_log_isolated_dir`, `expansion_store_isolated`, `cleanup_store_isolated` and `model_price_mirror_isolated` keep a test's writes out of the live `data/`. Nothing else is isolated by default: a test touching memory or `reply.db` takes `memory_isolated_dir`, `research_isolated_db` or `ask_isolated_db`. Unit tests inject fake LLM clients and memory writers and need no API credentials; the Tests workflow intentionally provides none.

## Runtime Shape

- `cli.py::DiscordBot` runs on `Intents.all()` minus `members` and `presences`.
- **Every cog's `setup(bot)` is sync and adds the cog with `override=True`**: cogs load inside `DiscordBot()` before any event loop runs, so an `async def setup` aborts boot with nextcord's `ExtensionFailed` (`tests/test_cogs_smoke.py::test_setup_functions_register_cogs`).
- **`on_connect` MUST call `add_all_application_commands()`; `on_ready` stays the only sync** (`DiscordBot.on_connect`, `tests/test_command_registry.py`). Every READY but a resume empties the registry, so each "Bot Connected" line marks a clear, and the next interaction whose guild does not resolve (a DM, a user install) sends nextcord's lazy-load `delete_unknown` pass over it, deleting every command until a restart, with nothing in `data/logs` saying so.
- **A long "Application commands synced" proves only a MISMATCH**: `register_application_command` POSTs for create and update alike.
- **A cog is a directory holding `__init__.py` and `cog.py`** (#403); `_load_cogs_sync` raises on a directory missing either but skips plain files and `_`-prefixed entries, so a stray `cogs/<name>.py` or `cogs/_<name>/` silently never loads.
- **`cogs/<name>/__init__.py` carries no re-exports**, or importing any helper under it runs the whole cog body; nothing but this line enforces it.
- **`services/` sits below the cogs** (#403): Discord-free (`tests/test_package_layering.py::test_services_never_reaches_discord`, transitively) and never importing `cogs/`; `utils/` and `typings/` hold no domain state and import from neither.
- **A module goes in `services/` only if a second cog needs it, an engine there needs it, or it is that engine's own vocabulary** (single-caller `services/memory/server_prompts.py` sits beside `prompts.py`); else it stays in its one cog directory. A feature with a Discord surface and a shared engine (economy, memory, each link platform) deliberately spans both.
- **`utils/link_errors.py` and `utils/scratch_dir.py` cannot move to `services/`**: nextcord-heavy `utils/expansion_placeholder.py` imports the first and `utils/` may not import `services/`; the second's path is hardcoded in `tests/test_scratch_dir.py`'s allowlist.
- **Adding a platform (one file in `services/platforms/`, behind `base.py`) touches two hardcoded name sets**, deliberate tripwires: `tests/test_link_source_shape.py::test_the_sweep_finds_every_source` and `tests/test_platform_shape.py::test_the_sweep_finds_every_downloader`.
- **No prefix command or `on_command_*` handler can fire**, since no `command_prefix` is passed; do not add one without a prefix. A raising slash command is logged only by `DiscordBot.on_application_command_error`.

## Cog Rules

- **Design a user-facing surface in an artifact before building it.** A panel, view, modal, embed layout or PNG board is settled on a published mockup (Discord-faithful chrome, both themes, real copy, every screen the flow reaches) carrying each open question with a recommendation, since moving a field in HTML costs minutes and in a shipped cog a rewrite; wording-only work skips this.
- **A permission the bot had is not one it has.** Server admins change channel overwrites without notice, so any channel REST call can answer `403 Missing Access`: log it at `warn` with the ids and no traceback (the one carve-out from `.github/CONTRIBUTING.md#logging`) and escalate nothing. A slash command answers on its own token without consulting channel permissions, so a reply landing proves no read access (#694), and anything that returns to such a message later (delete, edit, history read) must go through the interaction while its token is alive.
- **Never name a `View` button/select callback after a `View` attribute** (`refresh`, `stop`, `children`, ...): `View.__init__` rebinds the name to the item, and no type checker sees it because the decorator retypes the override, so `tests/test_view_callbacks.py` is the only guard.
- **One `commands.Cog` subclass per `cog.py`, and nothing under `cogs/<a>/` imports from `cogs/<b>/`**, helpers included. Reach across via the bot instance, `typings/`, `utils/` or `services/` (`tests/test_package_layering.py`).
- **Localize every user-facing slash command's name and description for English, `Locale.zh_TW` and `Locale.ja`.**
- **A root command passes `integration_types=INSTALL_CONTEXTS` and `contexts=INTERACTION_CONTEXTS` from `typings/commands.py`; subcommands pass neither**, since Discord reads both off the root. Omitting either silently removes a whole surface, and an unset `contexts` is not the documented `[0,1,2]` (`typings/commands.py`).
- **A shared slash-option vocabulary is a `Literal`, never a `StrEnum`**: nextcord turns `Literal[...]` members into choices (an explicit `choices=` overrides them) but rejects an arbitrary `StrEnum` subclass; `typings/video.py::VideoQuality` names the sites a new preset must reach. `SlashOption(default=...)` is typed `Any` upstream, so `ty` cannot check a default (`tests/test_download.py` reads it off the registered command).
- **Every user-visible command or behavior change updates `gen_reply/capabilities.md` in the same change.** With `/help` deleted it is the only description of any feature, so a command missing from it is one nobody, the answer model included, can find; `tests/test_capabilities.py` scans both ways (every runnable path documented, every documented `/command` a runnable path or group node), so write each command as a code span of its own.
- **Aligned-width embeds use `utils.discord_embeds.embed_spacer_payload(..., target=)`** so an edit reuses the uploaded spacer; re-uploading it on every edit trips Discord error 400009 on rapidly edited messages.
- **Content past embed limits is paginated or rendered to a PNG via `attachment://...`; never truncate silently.**
- **Markdown headings render reliably only inside `embed.description`.**
- **Never hardcode a Discord attachment-size ceiling; read it through `utils/media_delivery.py::upload_limit_for(guild=...)`.** Its guild path deliberately trusts nextcord's static `premium_tier` table, which over-reports 25 MiB for tier 0/1 against Discord's real 20 MiB base (10 MiB for two years before 2026-08-13), so it self-corrects when nextcord updates the table.
- **Decide attach vs host vs drop only in `MediaDeliveryPlanner.plan`; keep the Discord send and the degradation policy at each site**, since the sends are structurally disjoint. Pass `envelope_margin=MEDIA_ENVELOPE_MARGIN` for a combined attach or one riding with embeds, and keep every new site host-free under `MEDIA_HOSTING_ENABLED=false` (module docstring).

## AI Pipeline

### Backend and invariants

- **Every runtime conversation is `AsyncOpenAI` on the Responses API through the LiteLLM proxy (`OPENAI_BASE_URL`).** Never switch back to Chat Completions or import a provider-native SDK (`google-genai`, `anthropic`, `xai-sdk`) into any request path other than the non-proxied ones listed next; one SDK with any model hot-swappable by its model string is the point.
- **The non-proxied paths are the only direct-to-Google calls, and they forgo proxy-side cost/usage tracking**: attachment and linked-post Files API uploads (`gen_reply/attachment/gemini_file_api.py`, `gen_reply/files_api.py`), the YouTube answer turn (`gen_reply/interactions.py`), omni video (`VideoGenerator`, VIDEO route and `<generate-video>`), `<generate-music>` (`MusicGenerator`) and deep research (`cogs/research/`). They share three `cached_property` `genai.Client`s built from `config.gemini_api_key`; there is no client factory.
- **Every direct-to-Google generation call is `interactions.create`; `generate_content` must not come back.** Never read a `generate_content` or proxy result as what `interactions.create` can do, or back, since their capability gates differ (see Responses API Gotchas); read the `gemini-interactions-api` skill before writing an Interactions call.
- **Cast an `interactions.create()` result to a Protocol, as `generation.py::_InteractionResult` does.** `isinstance(x, AsyncIterator)` does not narrow `Interaction | AsyncStream[...]`, so every attribute read stays a `ty` `unresolved-attribute`.
- **Model strings live only in `RuntimeModelCatalog` (`typings/models.py`); pick a tier by whether the output's shape is already fixed.** `triage_model` fills a slot, `fast_model` composes prose short of the answer, `slow_model` writes the answer.
- **Look up which efforts a model accepts before repointing a tier, widening `EffortGrade`, or dispatching an existing tier down a new path; never trust a list in the repo, a comment, or memory.** The set is per-model, the vocabulary per-provider, and no effort is universal (2026-09-25: of 186 openrouter models listing efforts, `high` was on 180 and `low` on 158). Read `reasoning.supported_efforts` for the `<provider>/<name>` id at `https://openrouter.ai/api/v1/models`, not `supported_parameters` (it lists no values), and cross-check against the provider's own docs where they publish one: Google's thinking page matched openrouter exactly when last compared and is the only source for a snapshot openrouter lacks.
- **Through the proxy an out-of-set effort is an HTTP 200 from the fallback deployment on a non-streaming call and an error on a streaming one (no fallback there, see the retry bullet); direct to Google it is a hard failure (#459).** On a non-streaming call only the response's own `model` field proves which model answered, so a tier can look healthy for months and fail the first time a feature dispatches it direct to Google.
- **One `GEMINI_API_KEY` both uploads Files and backs the proxy's conversational aliases (`~/repo/litellm/configs/gemini.yaml`), so the proxy must never pool a conversational alias across keys.** A Files API file is readable only by the project that uploaded it, and a request naming files from two keys fails outright (measured 0/6); `gemini_lb1.yaml` / `_lb2.yaml` beside it carry only aliases that never see a Files uri (media generation, TTS, music, live, embeddings).
- **Pass `ReplyToolkit` (`gen_reply/toolkit.py`) explicitly, never through a `ContextVar`**, so a missed hand-off is a `ty` error.
- **Do not reintroduce per-key dispatch** (#582, removed in #620). A peak-hour 503 is upstream model capacity, not a per-project limit (#583: split evenly across keys, zero 429s), while per-key dispatch doubled Files uploads.
- **Author runtime prompts in English** (prompts, tool descriptions, `TTS_STYLE_DIRECTIVE`); reply language comes from the in-prompt "follow the user's language" rule. The deliberate exceptions are the few load-bearing Chinese notes in `COMMON_PROMPT` (e.g. the 轉帳 caution) and the bot's name 破貓.
- **IMAGE and VIDEO carry no default aesthetic; never reintroduce a code-side static style suffix**, which cannot honor "unless the user specified". Only MUSIC and VOICE keep a deployment default, plus VIDEO's spoken-language order.
- **Name LLM SDK objects `responses` and loop items `response`.**
- **Answer proxy-behavior questions from LiteLLM's source in the running container, not its docs, which lag it.** `~/repo/litellm/` is deployment config only (`ghcr.io/berriai/litellm:latest` with `pull_policy: always`, so no pinned version) and the uv env has no copy (#642). Use `docker exec litellm-litellm-1 python -c "import importlib.metadata as m; print(m.version('litellm'))"` and `/app/.venv/lib/python3.13/site-packages/litellm`, or shallow-clone upstream into a scratch dir for a version the container lacks.

### Reply pipeline (`gen_reply` orchestration)

- **One turn is one `ReplyPipeline` (`gen_reply/pipeline.py`); `cog.py` keeps only what belongs to the process.** Each phase is its own module (`routing.py`, `context.py`, `answer.py`, `media_reply.py`), and `research_bridge.py` is the whole cross-cog surface to `ResearchCogs`, which nothing may import directly.
- **`on_message` and `/ask` are two entry points into one turn, and `TurnSurface` (`surface.py`) is the whole difference** (#617). `/ask` is the only way into a server the bot was never added to, a group DM, or a DM between two other people; it lives on `ReplyGeneratorCogs` because a cog of its own would have to import across cogs.
- **Read where a turn happens off the surface (`guild_id`, `is_direct_message`, `surface.py`), not `message.guild`**: a synthesized `/ask` message's `guild` is None even in a server, so reading it files a guild turn's `source_only` observations under `dm/`. The one deliberate exception is server memory, which still reads `message.guild` and so stays off on `/ask` (`context.py::read_server_memory`).
- **Only `InteractionContextType.bot_dm` is a direct message**: `private_channel` also covers group DMs and other people's DMs, and a DM reading hands recall a `dm_partner_id` that opens every compartment the owner has.
- **On `/ask` the interaction token dies 15 minutes after invocation, and the deliverable and the failure notice 404 together, leaving a thinking state that never resolves** (#619). Both media routes generate inside `TurnSurface.delivery_budget_seconds` (`media_reply.py`); the inline `<generate-video>` marker and a QA stream hanging before its first delta are still not bounded by that budget, and neither fits that same fix (#628, open).
- **The effort grade is binary with `high` standing (#490) and as the fallback, and the model grades every message, blind spots included**: do not reintroduce a code-side grade (#493; the measurement is on `RouteClassifier.grade_effort`).
- **Every route takes the same ONE speculative `ReplyContext` (`ReplyContextBuilder.build`), built concurrently with the route.** IMAGE/VIDEO consume it after the media is on screen rather than cancel it, and the author's `tone_block` rides every route. A reply always reads memory with no caller-side switch to turn it off, so a test that must stay off the live store takes `memory_isolated_dir` (#576).
- **History is bounded on three axes, whichever binds first**: characters (`HISTORY_CHAR_BUDGET` plus `HISTORY_PER_MESSAGE_OVERHEAD` per message), attachments (`MAX_HISTORY_MEDIA_PARTS`) and message count (`HISTORY_MESSAGE_LIMIT`, a backstop that has never bound), all in `typings/context_budgets.py` beside their measurements (the first one, what uncapped attachments cost, is #579).
- **Progress is reactions on the user's message, never separate status messages** (`utils/reactions.py::ReactionStatusChain`).
- **A failed answer's error lands on the reply it was streaming into** (#587): `cog.py::_deliver_failure_notice` hands it to the streamer published in `turn_state.py::current_answer_streamer` (`land_failure`) and posts a fresh message when none is published or that returns False.
- **A test double whose `stream` fails must declare `carries_turn_notices`** (#588): otherwise `stream_answer_with_retry`'s read of it raises `AttributeError` in place of the staged failure, the persona reply's own `except Exception` swallows that too, and the test goes green having exercised nothing.
- **The streaming answer turn is the only LLM request the bot re-issues on an error, and the only one that needs it** (`streaming.py::stream_answer_with_retry`; `ImageGenerator.render`'s second attempt fires on an empty payload, not an error). LiteLLM's router applies `num_retries` and fallbacks to the non-streaming paths but gives a streaming `/v1/responses` request no fallback, so a provider 5xx arriving as a mid-stream SSE error frame reaches the client untouched (#586: 46 of 82 replies failed mid-stream in one 12h window, zero one-shot failures).
- **Read retryability structurally, never off the message, through `utils/llm_errors.py::llm_status_code` / `is_retryable_llm_error`**: a mid-stream failure is a bare `openai.APIError` carrying the status as the STRING `"503"` inside `exc.body["code"]`, so a check on `.status_code` alone retries nothing.
- **Best-effort media never raises into the pipeline's outer error path**: a voice / inline-image / inline-music / inline-video failure leaves the primary deliverable plus a ⏱️/⚠️ hint (`TurnSurface.hint`), and that hint is the streamer's alone, so an IMAGE or VIDEO persona-reply failure only logs. The 🔁 of an answer-stream retry goes through `TurnSurface.mark`, not `hint`: on the gateway it is an independent reaction that outlives the turn on purpose, as the mark that a delivered reply cost more than one attempt; on `/ask` `mark` drops it, so the only trace is the in-reply `Retrying...` notice, and only once a reply exists.
- **Kill-switches are the eleven `*_enabled` fields on `LLMConfig` (`typings/llm.py`), and each field's description states its own off-behaviour**; a marker-backed switch still strips its marker when off. The Gemini-key gate sits on the three `*_available` properties (deep research, music, video), in `answer.py` for YouTube and in `link_sources/registry.py` for Douyin / Bilibili.
- **Auto-expansion has no kill-switch**: `DouyinConfig.auto_expand_enabled` was deleted in #637 rather than mirrored onto Facebook, so stopping an expansion cog means deleting it.
- **`file_api_enabled` gates no feature but the mechanism under several**: it exists for a provider outage where the upload succeeds and the model then refuses the file, which costs the WHOLE reply since the answer carries the failing part (#500: 2026-08-14, every model but `gemini-3-flash-preview`).
- **Every turn record the anchored layer emits carries `message_id`, spans included, and every span is prefixed `gen_reply `** (#568): the console exporter teed to `./data/logs` prints a span only when it STARTS, never a completion line or duration, so an unanchored span drops out of the turn. The anchored layer is `cog.py`, `pipeline.py`, `routing.py`, `context.py`, `answer.py`, `media_reply.py`, `speculation.py`, `research_bridge.py`, `surface.py`, `streaming.py` and `input.py`; `generation.py` and `link_sources/*` deliberately carry no turn id, being bracketed within milliseconds by anchored records.
- **Attachment records cannot be joined to a turn, and that is unsolved**: `attachment/*` and `files_api.py` serve every turn concurrently, so two replies' upload records interleave with only `filename` / `cache_key` (`name` in `files_api.py`) to tell them apart, and `gen_reply attachment render done` is emitted both by `input.py` (keyed on whichever message it rendered: history, the replied-to message or the current one) and by `context.py::render_parts` (keyed on the turn). For the current message both carry the turn's `message_id`, so only their fields (`resolved`/`dropped` vs `elapsed_seconds`) tell them apart. To find why an attachment never reached the answer, start from `input.py`'s `gen_reply attachment render` pair for that source message.
- **`url_citations` on `gen_reply reply finalized` is None, never 0, on the Interactions backend**: it reports grounding in a shape the Responses event cannot carry (`interactions.py::adapt_interactions_stream`); see Responses API Gotchas before reading a zero.

### Routes

- **QA is the default route and the only one carrying the capability reference** (`gen_reply/capabilities.md`, injected by `AnswerTurn.stream_answer`); the media persona replies never see it.
- **An IMAGE edit loads its source images as raw bytes via `get_image_source_bytes`, never as Files-API handles**, since an edit needs pixels; the same bytes feed both `PromptGenerator.refine` and `ImageGenerator.render`.
- **YouTube is watched only on the native Interactions API** (`gen_reply/interactions.py` has why): a YouTube URL plus the QA-only `RouteClassification.watch_video` swaps that one answer turn to `create_interactions_answer_stream` when `AnswerTurn.stream_answer`'s gates pass; otherwise it stays on Responses and `gen_reply youtube watch declined` logs which gate refused. A backend swap, never a second pass.
- **Deep research (`cogs/research/`) goes direct to Google** because, spike-verified, the proxy 404s the Files API upload and its interactions transform is not a pass-through (it dropped `agent_config`); Antigravity `background=True` works despite the docs.
- **Deep research has exactly ONE tier**, `RuntimeModelCatalog.antigravity_model`, and no button under the report: do not reintroduce a tier, since a pricier upgrade is deliberately not a capability here (#447).
- **A research report follows the request's language; its status words stay English.**
- **Linked-post context** (Threads, Facebook, Instagram, Twitter, Douyin, Bilibili) is one registry of `LinkContextSource` entries, whose docstring holds the add-a-source recipe (`gen_reply/link_sources/registry.py`).
    - **Nothing is fetched until a QA route selects the source.** A builder starts only for a source in `RouteClassification.link_context_sources`, so an unselected link costs no fetch, download or upload; IMAGE/VIDEO never start one, and only the first URL is read.
    - **One grace per turn, never reset per source.** Every selected builder shares the `LINK_CONTEXT_GRACE_SECONDS` deadline fixed when the route returns, and each bounds its own media step with `LINK_MEDIA_TIMEOUT_SECONDS` so it degrades to text before the grace cancels it (`pipeline.py::_resolve_link_block`).
    - **A failed read injects the source's own notice, never an invented body**, so the model never says "I cannot open this link" (the reverted #294's failure), and a page's comment preload is stated as a fraction, never as "the comments". What the text says about media that could not be attached is the source's call: Threads lists the URLs, Instagram gives a bare count.
    - **A Douyin photo gallery can reach the model partially under the attached separator.** Douyin and Bilibili switch their separator on `if media_parts`, which is whole-or-nothing for a single clip but not for a gallery capped at `MAX_DOUYIN_INGEST_IMAGES`, uploaded per image with no count in the text; Threads names what is missing instead (`link_sources/threads.py::PostMedia`).
    - **Threads' quoted post counts against neither `MAX_THREADS_POSTS` nor `MAX_THREADS_REPLIES`.**
    - **`FILE_API_ENABLED=false` does not stop Threads' media being fetched.** Threads has no kill-switch of its own (`registry.py::_threads_media_ingest_allowed` is always True; only the Gemini-model and key checks gate it); every other source uses `_needs_files_api`, and Douyin/Bilibili add their own kill-switch on top.
    - **The URL comes from the current message, then at most one hop up, authored text only.** Only a `search_replied_to_message` source (Threads, Facebook, Instagram) falls back to the replied-to message, so replying to the bot's own expansion is not a trigger (`references.py::link_url_for_source` / `replied_to_message` have why).
- **Mention rule**: a message addressed to the bot (DM or explicit mention, `utils/mentions.py::is_addressed_to_bot`) is answered about, never auto-expanded; handing the model the URL instead saves nothing, since the proxy fetches and inlines it (see Responses API Gotchas). Gemini's `generateContent` resolves a remote https `file_data.file_uri` itself (#346, measured with a signed Threads CDN clip and a Douyin play URL), but whether `interactions.create`, the only direct surface allowed here, does the same is unmeasured.

### Inline markers (`markers.py`, `generation.py`)

- **The answer model picks what to speak and attach inside its own output** (`<generate-voice>` stays visible; `<generate-image>` / `<generate-music>` / `<generate-video>` are pulled): do not move that choice to a post-hoc classifier, which would not keep text, clip and media coherent.
- **A memory marker never chooses whose memory it writes**: `<write-memory>` / `<forget-memory>` (the person replied to) and `<write-server-memory>` (the community) are pulled like an image block (#596), and the scope comes from `message.author` / `message.guild` in `answer.py::_schedule_memory_updates`. What happens downstream is the Memory section's.
- **A link source that hands the model strangers' discussion runs it through `link_sources/__init__.py::defuse_markers`**, as Threads, Facebook, Instagram and Twitter do, or a quoted tag becomes a real render or a memory write. A Douyin caption or Bilibili title stays undefused under `COMMON_PROMPT`'s never-echo rule, whose measurement `tests/test_prompt_guards.py` owns.
- **The voice / image / music / video markers ride QA only and are deliberately separate from the IMAGE/VIDEO routes** (image-first UX): routing decides which runs, so they never double-fire, and those routes never speak or inline-image.
- **The bot's own music clip is re-ingested into later history on purpose**, unlike `reply.wav` (`input.py::_sources_from_parts`): the `<generate-music>` body is stripped from the reply, so the clip is the song's only trace.

### Attachments (`gen_reply/input.py`)

- **An attachment the slow model cannot read is dropped from both renders** (`MessageInputBuilder._supported_sources`, via `get_supported_modalities`), so the route, the effort grade, the selector and the answer never see it; the source media the image/video model works from skip that gate (`get_image_sources_with_mime`, `get_video_sources`).
- **A Discord forward has empty `content` / `embeds` / `attachments`; its payload is in `message.snapshots`**, which `input.py` folds into both the text and the attachment list.
- **Do not delete the commented `OpenAIFileUploader` / `AnthropicFileUploader` / `GrokFileUploader` branches or their modules as dead code**: they are scaffolding awaiting a verified reference path (`attachment/select.py::build_attachment_handler`).

### Responses API Gotchas

- **Role and part type pair strictly**: `user` / `system` / `developer` take `input_*` parts, `assistant` only `output_text` or `refusal`.
- **Behavior rules go in `instructions` (or `COMMON_PROMPT`), never an input-side wrapper**: `instructions` has `developer` authority over all of `input` but does not persist across turns.
- **Separator messages use `role=system`, not `developer`**, for Gemini and Claude compatibility through LiteLLM.
- **Run a builtin-tools-only positive control before reading any zero as no grounding**: the Responses bridge reports it ONLY as `url_citation` annotations (`vertexaisearch.../grounding-api-redirect/` urls) and never as `groundingMetadata`, which chat completions and the native API do carry along with `webSearchQueries`. Three separate investigations called a grounded reply ungrounded for want of one.
- **A function tool can share a Gemini request with `googleSearch` / `urlContext`, but each surface needs something different** (measured live 2026-07: proxy on LiteLLM 1.93.0, native both direct and via the byte-transparent `/gemini` pass-through): the proxy needs `include_server_side_tool_invocations: true` flat in `extra_body`, without which `_resolve_search_tool_conflict` silently strips the search tools (Google itself 400s the unflagged mix), and with it grounding holds on Responses (streaming too) and chat completions, pro as on flash. `interactions.create` rejects the flag (`Unknown parameter 'tool_config'`) and needs none for `gemini-3.1-pro-preview`, `gemini-3.1-flash-lite`, `gemini-3.5-flash` and `gemini-3.6-flash`, while both `*-latest` aliases were refused, so suspect a bare alias wherever a capability gate reads the model string.
- **Re-measure the mix with a prompt nonce plus `{"cache": {"no-cache": true}}` in `extra_body`, never from LiteLLM source alone or from one sample**: the proxy's `cache: true` key ignores `extra_body`, so a flagged request replays an unflagged answer, and the drop warning is deduplicated, so it is no per-request signal.
- **A function call and a grounded answer never share a turn** (2026-07, N=20 per condition on `slow_model`, #409): the call ends the turn with empty text (145/145; whether a search ran on it is unmeasurable), and the next turn with the tool result grounds (19/20); streaming behaved the same, which #409 does not record.
- **Three measured traps before adding a function tool to a turn that searches**: no runtime call sends `extra_body`, so a tool without the flag silently ends grounding on every QA reply; merely offering it drew a call on pure-search questions 20/20, which the old `MEMORY_SELECT_PROMPT` restraint wording did not fix (10/14; `RECALL_SELECT_PROMPT`'s is unmeasured) and a sentence exempting live-external-fact questions did (0/14); and naming a tool in `instructions` without attaching it makes the model hallucinate the call (3/12), ending the turn.
- **Never put a mock-testing key in `extra_body`, whatever its value**: since LiteLLM 1.96 `proxy/route_llm_request.py::raise_if_mock_testing_params_disallowed` 400s on the name alone unless `general_settings.dangerously_allow_mock_testing_request_params` is true, which is how the old no-op `{"mock_testing_fallbacks": False}` took down the whole reply pipeline (#496). The deployed proxy sets that opt-in (`~/repo/litellm/litellm.yaml`), so a mock key is not refused there: a falsy value does nothing and a truthy one injects a real synthetic failure into production traffic.
- **Media reaches the model by upload, never by URL**: upload to the Gemini Files API (`gen_reply/files_api.py`) and pass the full `https://.../files/<id>` uri as an `input_file` `file_id`; bytes in hand may go as a `data:` URI (`tests/test_model_media_parts.py` enforces it and has why).
- **Pricing comes from `utils/model_pricing.py`'s cached LiteLLM table; never hardcode rates.** Its recovery (`cli.py::price_table_task`) deliberately never refetches a table upstream already served: rate drift is a separate question (#473).

## Economy

- **Economy identity is cross-server: `UserAccount` has no `guild_id`.** Money columns are `StoredInteger` decimal text parsed to Python `int` (`utils/stored_integer.py` has why).
- **`total_earned - total_spent == balance` must hold:** every applied positive delta bumps `total_earned`, every negative one bumps `total_spent`. There is no transaction table.
- **Money inputs are string `SlashOption`s parsed by `utils.amount_parsing.parse_decimal_amount`;** malformed text gets an ephemeral `build_invalid_amount_embed` before any mutation. Reuse it for any number that can exceed Discord's int cap.
- **`UserAccount.avatar_url` is a last-seen cache (`utils.avatars.guild_avatar_url`); do not backfill existing URLs.**
- **`credit_with_repayment` is the single income facade** (message reward, casino payout); despite the name it repays nothing.
- **Central-bank minting is bounded by the pool and the per-borrower ceiling, never by the approver.** Approval is any server administrator (`CentralBankLoanDecisionView._is_guild_admin`), which anyone becomes by creating a server.
- **The pool's collateral is per guild; its debt is the whole bank's.** `guild_participant` is recorded only for a rewarded message's author and a `/central_bank` caller, never a `member:` target.
- **Repaid interest is kept in `central_bank_ledger` and lent again, not burned;** it cannot be farmed (measured: a borrow-at-100%-and-repay loop only ever lost the attacker money). Keep `ECONOMY_ALLOW_CENTRAL_BANK_SELF_APPROVAL` unset or `false` in production.
- **Admin tweaks go through `adjust_balance(..., allow_negative=...)`, never a casino settlement helper.**
- **Every write path must call `invalidate_economy_leaderboard_cache()`.**
- **House P&L is the `casino_ledger` row, never the bot's `user_wallet`.** Player wallet and ledger commit in one transaction, and Blackjack settles through `apply_blackjack_settlement`, never `apply_round_settlement` directly.
- **Shared social, market and settlement events are public embeds with scheduled cleanup; personal state, malformed-amount and permission failures are ephemeral.** A validation failure found after the public defer (`/give`, `/games`) is a public expiring embed.
- **Exactly one faucet pays an action reward, `cli.py`'s cooldown-gated per-message reward;** other cogs must not add a second (the system-funded mints that settle a loan or a game are not rewards).
- **`apply_vip_blackjack_bonus` and the loan-rate converters stay in `typings/economy.py`,** so code that only formats or settles a number never imports the ledger's engine module (#610).

## Games

- **Game rules stay pure in `games/blackjack.py` and `dragon_gate.py`.** `lobby.py`'s base views keep `raise NotImplementedError`; do not convert them to `abc.ABC`.
- **No LLM anywhere in the games:** do not reintroduce the removed casino `SystemNarrator` banter, the bot-player `reason` text or any AI bot-player. The dealer is a label, not a Discord identity, and posts no narrator messages.
- **A round settles in one atomic step after it resolves:** validate or clamp bets up front, then settle through the helpers.
- **過五關 is a house rule:** a 5+ card non-bust hand auto-stands and wins regardless of dealer total, except a five-card 21 (`blackjack.py::settle_hand`, `settlement.py::settle_blackjack_player`).
- **The bot joins every Blackjack table as a regular player whenever its wallet is above zero, and settles like any human.**
- **Raising `MAX_BLACKJACK_PLAYERS` (6, `blackjack_views.py`) means re-deriving `shoe.py::RESHUFFLE_THRESHOLD_CARDS`.** The threshold is sized to six seats' worst-case draw and nothing tests the pair, so an undersized one silently corrupts the count mid-round.
- **Action buttons are presence-based: an invalid control is removed, not disabled.** Keep the peek a two-stage animation (`_animate_peek_locked`), `self.stop()` before settlement in `_finalize_locked`, and terminal public messages deleted through `utils.message_cleanup` rather than a cog-local loop.
- **`data/database/games.db` carries two separate engines, `cogs/games/` and `utils/message_cleanup.py`, on purpose.**
- **Dragon Gate settles against the shared `jackpot_pool` row `game_id="dragon_gate"` through the jackpot helpers, never the casino ledger.**

## Memory

- **The path is the privacy boundary** (#408): each fact is one file under `data/memories/<user_id>/` in the compartment allowed to read it (`global/`, `g/<guild_id>/`, `dm/`), beside `detail.md`, `raw.md` (deliberately one file) and `tone.md`. Do not move it into SQLite and do not add fallbacks for the pre-#408 layout (`main.md`, `main.bak.md`, the `v1` header); `store.py`'s docstring has the layout.
- **The model never chooses a fact id or filename**: code mints it from compartment + summary (`facts.py::mint_fact_id`), which is what makes path traversal structurally impossible.
- **Keep the compartment boundary structural, not a prompt rule**: each consolidation call sees only the evidence routed to the compartment it writes (`consolidation.py::_consolidate_locked`). Information flows global -> guild, never guild -> global.
- **Pre-#464 prose `member_alias` rows are not backfilled**: `scripts/regen_memories.py` reaches a server scope only as a full evidence rebuild, and a row self-heals on the member's next observation.
- **Reject a consolidation batch for shape errors only**: a failed LLM call, or the net-delete cap (exempt on the regeneration path). Everything else sanitizes per delta, since a whole-batch rejection re-derived from the same inputs is a permanent freeze, not a retry; read `deltas.py::_resolve_delta` before assuming what a bad delta costs.
- **Aging is code, not prompt prose** (`deltas.py::sweep_stale_facts`).
- **Read caching is mandatory**: `recall_user_memories` is synchronous and can carry 8 users per reply, so `read_memory_document` is cached against a per-scope write generation. It is exact only because every write goes through the store, which bumps that generation, so editing the tree out of process while the bot runs is unsupported.
- **The answer model decides what to remember, inline** (#596): the three memory markers (see Inline markers) replaced the extraction pass, so do not reintroduce `MemoryWriterAI.extract` or the `PHASE1_PROMPT` / `SERVER_PHASE1_PROMPT` pair.
- **The pending memory note is a promise answered exactly once**: a turn carrying `<write-memory>` or `<forget-memory>` shows `MEMORY_PENDING_NOTE` only where something can take it back (`streaming.py::_wants_pending_memory_note`), and `pipeline.py::_run_memory_update` answers `report` on every exit, an empty `MemoryWriteSummary` included.
- **The review is fire-and-forget and must never add reply-path latency**; an LLM failure keeps the previous state.
- **A forget is evidence, never a delete**: `<forget-memory>` writes a `### forget_request` into `raw.md` and consolidation emits the `delete` in a `deletes_only` call, so a forget can only remove a fact, no fact id reaches the answer prompt and the reply path grows no delete capability. `apply_deltas` drops the corrective `update` that `PHASE2_PROMPT`'s FORGET REQUESTS block still asks for (`deltas.py::partition_forget_requests` has the routing).
- **The sharing gate is tighten-only, and code owns every rule but one.** The one prompt-owned rule is `PHASE1_EVALUATOR_PROMPT`'s: naming or describing anyone but the target is `source_only` even with no id token (the code rules are in `writer.py::_sanitize_observation`). **Do not add a Chinese pronoun/relation lexicon**: #408 measured it re-locking 14.5% of all `global` observations.
- **Anti-injection is plumbing in `writer.py` (plus `utils/llm_transcript.py::sanitize_identity`), not wording in `prompts.py`**; prompts treat conversation content as data, never instructions.
- **Recall is deterministic first, an optional selector second.** Code always resolves the current author, the replied-to message's author (one hop) and current-message mentions, in that order (`context.py::_resolve_recall_candidates`), and `recall_user_memories` enforces both that allowlist and the compartment boundary (`recall.py::compartments_for_reading`). Only a public guild channel with extra ids in the rendered `## 成員稱呼` table runs `ReplyContextBuilder.select_recalled_memories`, whose failure loses only that optional memory and which never displaces a deterministic participant.
- **Neither note review sees stored memory.** The personal review gets a target-centered list (`writer.py::target_centered_memory_messages`) and the server review the whole `ReplyContext.message_list`; neither carries a memory block, so neither can re-ingest what is already stored.
- **Memory content stays in markdown; `reply.db` (`memory_job` / `memory_token_clock`) persists only the review's progress.** Every memory DB write but the clear's tombstone goes through best-effort `inflight.safe_db_write` (`services/memory/database.py` has the state machine).
- **`memory_job` gains no columns for the marker notes.** Nothing migrates this schema and `clear_job` is not best-effort, so a new column takes `/memory clear` down on a deployed bot; the notes ride inside `transcript` (`writer.py::render_turn_payload`).
- **`tone.md` is the one tier outside the compartment tree: keep it unpartitioned and never fold its call into the `global` compartment's**, which would demote the boundary back to a prompt rule. ~48% of observations are `source_only`, so a global-only note would stop updating for half of all conversations (`tone.py`).
- **`regeneration.py::regenerate_scope_memory` is the ONE path allowed `allow_mass_delete=True`**, shared by `/memory regenerate` and `scripts/regen_memories.py`, the one offline entry point. Do not describe the two as equivalent: only the command runs inside the bot under `scope_lock`, while the script is a second process whose closing `clear_raw` unlinks whatever `raw.md` gained while it ran.
- **`data/memories` is a local git repository, never pushed** (`git_history.py`, `MEMORY_GIT_ENABLED`). A `/memory clear` commits the deletion and deliberately does not erase the history behind it (#408).
- **Every store write except the clear's serializes under `scope_lock(scope)`.** The clear skips the lock on purpose, so every file write must sit right after its `cleared_since` check with no `await` in between or an in-flight update resurrects what was cleared (`pipeline.py::clear_scope_memory`). Tests take `memory_isolated_dir`, which also turns the git committer off.
- **`scope` is the owner key and `compartment` the visibility axis; they are never the same word.** `user_scope` / `server_scope` build a scope and `store.py::flavor_of` reads its flavor back, so one store and one pipeline serve both flavors.
- **`pipeline.py` is one turn's memory lifetime alone** (#607, #613): the note review and the clear that ends it. Everything else sits below it (`consolidation.py`, `inflight.py`, `regeneration.py`, `tone.py`) and every edge points down; nothing in the package imports `pipeline.py` (`tests/test_package_layering.py::test_nothing_inside_the_memory_package_imports_its_entry_point`).
- **Server memory is `data/memories/bot_memories/<server_id>/global/`, exactly ONE compartment with no second writer**, since its observations carry no source or sharing to route by. `## 成員稱呼` is the sole carve-out from its no-individuals rule, recorded `durability=permanent`; `gen_reply` reads it whenever `message.guild` resolves (`ReplyContextBuilder.read_server_memory`) but reviews `<write-server-memory>` notes only where `references.source_channel_is_public` holds, and DMs skip both.
- **`/memory` commands change the personal scope only.** Community memory is operator-maintained: `/memory server show` is read-only and there is no server-side clear.
- **Every clear goes through `pipeline.py::clear_scope_memory`**; `/memory clear` only opens `MemoryClearConfirmView`, whose button calls it. A clear is whole only when all four holdings are neutralized (its docstring), so an offline wipe with the bot stopped must also create a tombstone or remove that scope's row, and an online clear must use this protocol because staging writers can still exist.
- **A test reading a DEFERRED turn's `memory_job` row must first drain `inflight._db_tasks`** through `tests/test_memory.py::_wait_for_persisted_writes`.

## Other Cogs

- **An auto-expansion cog subclasses `utils/expansion_cog.py::ExpansionCog` and supplies only its card**: URL pattern, constants, a `read` that raises and a `build_delivery` returning the card or None. It must not override the listener or `_expand`, spell a status mark, or decide a shared outcome itself; `tests/test_expansion_contract.py` enforces that, and its one written-down list fails until a new cog is added.
- **An expansion cog and an AI link source are a pair, and matching the existing ones is the default; diverging needs a reason.** Each of the five expanding cogs is also a `LINK_CONTEXT_SOURCES` entry, so a new cog is not done until its reply path is built or why not is written down, and whether its parser carries the shared conversation shape is decided (`tests/test_link_source_shape.py`); both hold in reverse for a new registry source.
- **Bilibili (a registry source with no cog) and YouTube (not a source, see `watch_video`) are AI-only on purpose, because of length.** A post on the five expanding platforms is bounded by what anyone may upload there, while these links can be a four-hour video that expanding would download and post; the answer path is bounded instead by `gen_reply/link_sources/bilibili.py::MAX_BILIBILI_INGEST_DURATION_SECONDS` (metadata only past it) and, for YouTube, by what Google's server-side fetch and the model accept.
- **A platform reader raises `utils/link_errors.py` classes (or parents its own onto them), and the shell picks the reaction and log severity off the class** (`expansion_failure_emoji` / `report_expansion_read_failure`), never an `isinstance` in a cog. `LinkUnavailableError` (⚠️) only when the platform itself says there is no post, `LinkRetryableError` (⏱️) when it refused or stalled and the same link works later; swapping them tells someone a working link is dead (#645).
- **Every request site classifies its failure, media downloads included, and never by testing a `requests` response for truth** (`Response.__bool__` is `self.ok`, so a 429 or 503 is falsy). `link_fetch_error` / `is_retryable_fetch_failure` are the shared classifiers, and `link_fetch_error` leaves a 403 a bare `RuntimeError` until there is evidence about that platform.
- **`parse_threads` shows at most ten embeds and counts the rest in the target's footer (`_remainder_notes`), and a URL it publishes must never name whoever shared the post** (`services/platforms/threads.py::ThreadsDownloader._build_conversation`). Do not reintroduce the `total_size` byte guard (media hosting replaced it), a media-count guard, or the permalink follow-up replies (#645), which landed below the card they described.
- **Threads, Facebook, Instagram and Twitter share one conversation shape**: each `services/platforms/<platform>.py` exposes `parse_metadata(*, url=)` returning a `<Platform>Conversation` built on `base.py::PlatformConversation` / `PlatformOutput`, so one function builds AI input from any of them (`tests/test_link_source_shape.py` asserts the surface per platform). `chain` is one post on Facebook and Instagram, one or two on Twitter, a real chain only on Threads.
- **Build a conversation once and never mutate it**: `target` is a `cached_property`, which pydantic does not invalidate on a `chain` append or reassignment.
- **A platform's extras live on its own `<Platform>Output`, and a field it never publishes is not added**: no `share_count` on Instagram, no `retweet_count` on Twitter (published only for an embedded post). Threads' `Post` schema mirror keeps Threads' own names (`reply_count`, `reshare_count`); the Output model is where the vocabularies converge.
- **Only Threads has a `parse` context manager, and that is the rule, not a gap**: `parse` exists to clean up a download, and of the four only Threads downloads a file.
- **The Facebook, Instagram and Twitter expansion cogs download nothing**: images ride as URLs Discord fetches, so they have no scratch directory, no media-delivery planner and no size ceiling, and the four-image cap bounds a rendered message, not a `context_budgets` value. On Twitter that is a choice rather than a limit (the mp4 is fetchable); a deployment wanting the file has `/download_video`.
- **Threads card images ride as CDN URLs on purpose** (uploading them, #721, was reverted as too heavy): Discord probes a linked embed image once at send and stores a failed probe as a 0x0 image it never retries, so a card occasionally goes out missing an image (2 of 23 Meta CDN images on 2026-09-26). That is the accepted cost; do not bring the upload back unasked.
- **Discord merges embeds that share a URL**: that is what makes the extra image embeds one gallery, so Facebook's grey `?comment_id=` card carries its own URL to stay out of it.
- **Platform reaction markers live in `typings/emojis.py`**, since an expansion cog and `gen_reply` put the same one on a message and cogs may not import each other; `tests/test_link_source_emojis.py` pins every registered source to an entry.
- **The Douyin expansion states no reason in the channel, like every expansion cog**: its reaction is the whole report, and `douyin_failure_message` exists only for `/download_video`, whose failure is its answer.
- **`DouyinDownloader._download_to`'s `max_bytes` is a fail-fast guard, not a policy**: `/download_video` and `parse_douyin` pass `None` (oversize is the media host's job), the AI path only the Files API's 2 GB ceiling.
- **A lone hosted clip from `video/cog.py` must be the message's only URL**: a second one, even `<>`-wrapped, stops Discord rendering the inline player, so `_deliver_url` omits the source line the native path and an all-hosted Douyin gallery keep.
- **Scratch downloads go in a per-invocation `utils/scratch_dir.py::scratch_directory` under the system temp dir, never under `data/` and never via `tempfile.TemporaryDirectory` / `mkdtemp`** (`tests/test_scratch_dir.py`): `asyncio.to_thread` cannot be cancelled, so removing the directory is what stops an abandoned writer.
- **A writer into that directory never re-creates it**: mkdir once up front, since a mkdir between files rebuilds the directory the give-up removed as its stop signal (`services/platforms/file_downloads.py::stream_to_file`; `utils/scratch_dir.py` has the yt-dlp exception).
- **`cogs/template/` is a real loaded cog, not a scaffold to copy or delete**: it owns `/ping` plus message-trigger reactions that `gen_reply/capabilities.md` does not mention.
- **Never let `media_cleanup`'s sweep run in a test**: it deletes against the env-resolved live serve dir, so test the gate only.
- **Usage records are one JSON line per slash invocation and per AI reply in `data/usage/<YYYY-MM>.jsonl`** (`utils/usage_log.py`, #429); a research run gets no record of its own, since its launch is already a `reply.db` `research` row and the `/deep_research` or `QA` turn that started it is recorded as usual; the empty-prompt `?` path writes no `reply` record. `scripts/usage_report.py` names only what was used, so a zero-use inventory comes from `gen_reply/capabilities.md`.
- **A test cog built via `__new__` must be handed a `UsageRecorder` explicitly** (`tests/test_gen_reply.py::_cog`).

## Conventions

- **Config classes are `pydantic_settings.BaseSettings` with an explicit `validation_alias=AliasChoices("ENV_NAME")`**; `.env` is loaded at import time.
- **Pure shared result types, enums and constants go in `typings/`** when they depend on no cog or util.
- **Structured data is a `pydantic.BaseModel`, service and helper classes included**: no `dataclass`, no loose `object` / `Any`. Every field carries `Field(description=...)` (plus `examples=` where useful), a required one as `Field(..., description=...)`.
- **A cap on how much content one model request carries lives in `typings/context_budgets.py`**: one whose binding leaves the model seeing LESS while the request still goes out (the module docstring lists what stays out). No name scan enforces this.
- **A wall-clock bound whose expiry produces a failure or a degradation lives in `typings/timeouts.py`** (#529; enforced by `tests/test_timeouts.py`). A wrapper around one LLM call purely as a liveness backstop belongs nowhere (module docstring).
- **Log severity follows the ladder in `.github/CONTRIBUTING.md#logging`**, which also owns exception attachment and broad `except`.
- **Ruff formats and lints; `ty` is the only type checker** (mypy removed in #356, see `pyproject.toml`). A `# noqa` names its rule and a reason.
- **`ty` types a pydantic field of a class pydantic cannot model (`nextcord.Message`, `genai.Client`, `AsyncOpenAI`) as `Any` in the synthesized `__init__`**, so a wrong handle handed to a `gen_reply/` service surfaces only at runtime; modelled types stay checked (`int` becomes `LaxInt`). `SkipValidation[T]` does not change the signature, only runtime validation.
- **Call with keyword arguments, single-argument calls included**; no bare `*`. Positional idioms allowed: `len(x)`, `str(x)`, `Path("x")`, exception constructors, variadic collectors, `logfire.info("message")`.
- **No intermediate one-level aliases** such as `usage = responses.usage`.
- **Import functions by name and call them unqualified**; a module-namespace import is a last resort with a reason.
- **Every async SQLite database opens through `utils/sqlite_config.py::SqliteBootstrap`** (#608), each module keeping a module-level `_engine`, never a `cached_property`. Readiness is keyed on engine identity, so tests swap `_engine` instead of resetting it by hand.
- **No `asyncio.Lock` / `Semaphore` / loop-bound registry may outlive one event loop**: each test runs on a fresh loop and raises `is bound to a different event loop`, and building it lazily does not help. Use `utils/asyncio_locks.py`'s `LoopLocalLock` / `LoopLocalSemaphore` / `LoopLocalRegistry` / `KeyedLockManager`.
- **`docs/` is generated by `make gen-docs`; never hand-edit it.** Do not touch the README badge block unless explicitly asked.

## Documentation Split

- **`README.md` is the canonical user-facing README**; `README.zh-CN.md` / `README.zh-TW.md` mirror its structure, `.github/CONTRIBUTING.md` is for developers, `CLAUDE.md` for agents.
- **The reply pipeline's visual companion is the Artifact `https://claude.ai/code/artifact/a430046d-dd13-4d85-99ac-dd46b434f243`**, never a source; a change to the pipeline's SHAPE (a route, a trigger condition, an endpoint or SDK a feature dispatches on, a model tier, a kill-switch) updates it in the same change. Update it IN PLACE by passing that URL to the publish, or a SECOND artifact is silently minted; it is private and the URL alone grants nothing.
- **`README.md`'s "How a reply happens" mermaid, mirrored into both translated READMEs, is a condensed copy**: those three and the artifact move together or not at all.
